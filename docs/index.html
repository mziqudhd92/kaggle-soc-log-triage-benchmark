Smarter Log Triage: Why Cheap Flash LLMs Master SOC Context Discipline

We benchmarked flagship LLMs against cheap Flash models on L1 log triage. Here is what your API bill actually buys.

Executive Summary

Security teams are routinely sold “frontier models for the SOC.” We asked a narrower, money-relevant question: On short first-pass log triage, do expensive flagship models beat cheap Flash/Nano models by enough to justify the bill?

We built SOC Log Triage (LT): 22 synthetic log bundles (8 minimal-pair twins + 6 controls) evaluated against four gold labels (attack, misconfig, noise, needs_more_data), paired with a separate panic trap measuring false alarms on non-attack events.

The 30-Second Takeaway
The Delta That Matters: Top expensive models (Claude Sonnet 5, GPT-5.6 Luna) score 0.961 LT, while top cheap models (Gemini 3.8 / 3.7 Flash) score 0.894 LT — a modest +0.067 (~7%) performance gap.
False Alarm Parity: Cheap Flash models match flagships on panic trap calmness (1.000 score), showing no tendency to overreact to scary strings like /etc/passwd.
More Expensive ≠ Better: Flagships like GPT-5.5 (0.571) and GPT-5.6 Sol (0.793) were routinely beaten by Flash models due to context discipline failures or output formatting collapses.
The Policy Rule: Route high-volume L1 triage to Flash/Nano models. Pay for top-tier frontier models only on escalated items where a 7-point accuracy bump is worth 10x–20x higher API costs.

1. The $10 / M Token SOC Trap

An L1 SOC night shift is not “find a CVE in a repo.” It is a relentlessly fast stream of noisy evidence packs:

  • Tens of thousands of /wp-admin HTTP 404s
  • An AccessDenied spike directly following a CI/CD deploy
  • A truncated POST /api/transfer line missing its HTTP status code
  • Kube-probe hitting /healthz every 10 seconds

When you paste these into an uncalibrated LLM and ask “Is this an attack?”, many models panic on scary tokens. That isn’t threat detection — it is alert fatigue with a chatbot face, costing $10+ per million tokens.

Public LLM leaderboards miss this nuance. Coding benchmarks ask “Did you find a bug?” Chat benchmarks ask “Are you helpful?” Neither asks:

  1. Did you separate attack from misconfig from noise?
  2. Did you abstain when the shipper truncated the log line?
  3. Did paying 10x more buy any real accuracy?

SOC Log Triage is a diagnostic probe. Small dataset sizes with minimal-pair twins allow single context-discipline failures to register clearly, showing whether a model reads control facts or merely acts on keyword impressions.

2. Testing Context Discipline, Not Token Panic

We borrow the minimal-pair twin discipline from linguistics: two log lines that share scary surface features, where exactly one control fact flips the gold label.

The Gold Taxonomy

LabelMeaning
attack Evidence of active exploitation or compromise in progress.
misconfig Config / IAM / CORS / debug errors following a change without active exploitation.
noise Expected background traffic (health checks, blocked generic scanners).
needs_more_data Incomplete or truncated logs. Forces abstention instead of guessing.

Attack accuracy is weighted highest (0.35) because missed compromises carry the highest business severity, while noise and abstention share the remaining mass to reward queue calmness.

3. Dissecting Minimal Pairs — The Twin Method

The dataset (N=22, frozen in git) contains 16 minimal-pair twin items (8 pairs) and 6 unpaired control anchors. Here is how tiny control facts flip the diagnosis:

Deep Dive 1: Web Reconnaissance — twin_wp_probe

Shared Surface: Requests targeting /wp-login.php, /xmlrpc.php, and /.env.

Attack variant
Distributed requests originating from multiple external IPs (203.0.113.*, 198.51.100.*).

Gold: attack

Noise variant
Requests originating from a single egress IP (34.102.136.180) with User-Agent IridiumCI/1.0 and a comment noting a scheduled scan.

Gold: noise

Why it matters: The path list alone is not a compromise. A model that labels both attack failed context reading.

Deep Dive 2: Cloud IAM Escalation — twin_iam_denied

Shared Surface: AccessDenied events targeting sensitive bucket prod-invoices.

Misconfig variant
Errors occurring immediately after an automated deploy-bot policy update removed s3:GetObject.

Gold: misconfig

Attack variant
Unknown OIDC session (MFA=false) executing successful bulk s3:GetObject downloads following an initial denial.

Gold: attack

Why it matters: AccessDenied after a deploy bot policy tighten is a post-deploy outage. Bulk GetObject after a shady AssumeRole is exfiltration.

5. Panic Trap — False Alarms Are Already Solved

When asked directly “Is there a confirmed active attack or compromise right now?” on the 10 noise/misconfig items, Flash/Nano models and expensive flagships both score 1.000.

Paying more does not buy calmer behavior. Modern lightweight models no longer scream “attack” at every kube-probe or blocked vulnerability scanner. The separation between model tiers lives entirely in fine-grained taxonomy classification and explicit abstention on truncated logs.

Headline Metric
Panic Gap: share of noise / misconfig items wrongly called attack. Zero means calm triage; high means alert fatigue.
Observed: 1.000 across Flash and top flagships — the panic trap is already solved.

6. Actionable SOC AI Engineering Playbook

Security engineering teams should structure LLM triage pipelines around tiered routing rather than defaulting to flagship models:

[ Raw Ingest Log Stream ] │ ▼ [ Step 1: L1 Triage Filter ] Model: Gemini 3.8 / 3.7 Flash Cost: ~$0.10 / M Tokens │ ┌─────────────┴─────────────┐ ▼ ▼ [ High Uncertainty / Truncated ] [ High Confidence ] LT Label: needs_more_data LT Label: noise / misconfig or Low Classification Margin or Clear attack │ │ ▼ ▼ [ Step 2: Escalated L2 Audit ] [ Auto-Route / SIEM Action ] Model: Sonnet 5 / GPT-5.6 Luna Log to SIEM / Silent Drop Cost: ~$3.00–$15.00 / M Tokens

Three Rules for SOC Buyers

  1. Default to Flash: Route 100% of initial log volume through Flash / Nano models.
  2. Escalate by Exception: Reserve Claude Sonnet 5 or GPT-5.6 Luna for the hard slice where logs emit needs_more_data or high ambiguity.
  3. Audit Vendor Pitches: Never buy “security AI” on a chat demo of one scary line. Demand twin-based triage benchmarks and false-alarm scores.
